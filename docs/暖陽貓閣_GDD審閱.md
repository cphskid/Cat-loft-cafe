# 《暖陽貓閣》GDD 審閱報告

審閱對象：初版 GDD（Scratch 3.0 目標）
結論先講：核心概念清楚、氛圍定位好，時間換算也算對了。最需要先處理的是 **三個會直接卡住開發的問題**：

1. **☁ 雲端變數用法錯誤**（P0，會讓遊戲無法正常運作）
2. **缺少經濟數值、勝敗條件與階段升級條件**（P0，沒有這些就無法開始調數值）
3. **規模超出 Scratch 單人專案的合理範圍**（P1，建議切出 MVP）

以下依優先度排列。

---

## P0｜必須先修正

### 1. 雲端變數（☁）不能這樣用

文件中 8 個全域變數全部標成 ☁，在 Scratch 會出問題：

| Scratch 雲端變數限制 | 對本作的影響 |
|---|---|
| 所有玩家**共用同一個值** | A 玩家賺的金幣、遊戲時間會被 B 玩家覆蓋。`Game_Time_Mins`、`Current_Floor` 這種每幀變動、純個人的狀態尤其不能上雲 |
| 只能存**數字** | 無法直接存名字、清單 |
| 每個專案最多 **10 個** | 已用 8 個，之後不夠擴充 |
| 寫入有頻率限制（約每秒數次） | 時間每幀更新會被節流甚至中斷連線 |
| 只有登入且非 New Scratcher 才能寫入 | 多數小朋友玩家無法存檔 |

**建議：**
- 全部改成一般全域變數（拿掉 ☁）。
- 存檔改用 **「存檔碼」**：結算時把 Gold、Fame、Fans、Day、員工/貓好感等組成一串數字字串，讓玩家複製；讀檔時貼上解碼。這是 Scratch 經營遊戲的標準做法。
- 如果真的想用雲端，只留一個「全球累計吸貓次數」或「排行榜」這類**本來就該共享**的數據。

### 2. 數值不一致

| 位置 | 問題 | 建議 |
|---|---|---|
| `Fame_Level (1 ~ 4)` vs 第 4 章只有 Stage 1–3 | Lv.4 沒有定義內容 | 二選一：改成 1~3，或補一個 Stage 4（例如「排隊名店／二號店」作為終局） |
| `Restroom_Dirt_Level (0 ~ 3)` vs「3~4 名顧客如廁後轉黃色驚嘆號」vs「擦除 3 處污漬」 | 三個「3」意義不同，且「3~4 人」是隨機還是固定沒寫 | 定義成：每位如廁顧客 +1 髒污；`Dirt ≥ 3` 顯示驚嘆號；小遊戲污漬數 = 當前 Dirt 值（上限 4）。這樣三者就連起來了 |
| 除臭機「降低**異味**累積速率 50%」 | 變數表沒有「異味」，只有髒污 | 改成「每位顧客髒污 +0.5」，或新增 `Restroom_Odor` 變數 |
| `Store_Cleanliness (0~100)` 與 `Restroom_Dirt_Level` | 兩者關係沒定義，大掃除提升的是哪一個也不清楚 | 例如：洗手間每髒 1 級，整潔度每遊戲小時 -5；大掃除一次 +30 |
| 「一星差評」「星級評價」「累積好評」「評分扣除」 | **沒有任何評分變數** | 新增 `Rating_Today`（平均星數）與 `Review_Count`，並寫明它如何影響 Fans |
| `cat_state` 1 活動 / 2 睡眠 / 3 飢餓 | 互斥狀態，但「又睏又餓」是會同時發生的；逗貓員負責的「玩耍度」也沒有對應變數 | 改成三個獨立數值：`cat_energy`、`cat_hunger`、`cat_mood`（0~100），state 由數值推導 |
| 地圖圖示是「上下兩層同時顯示的剖面圖」 vs `Current_Floor` 切換視角 | 兩種呈現方式互斥 | 見 P1-4 |

### 3. 時間系統：換算正確，但節奏與實作需調整

換算核對：07:00→21:00 = 14 小時 = 840 遊戲分鐘 ÷ 4 = **210 秒** ✅，`420 = 07:00`、`1260 = 21:00` ✅。

各時段實際長度：

| 時段 | 遊戲時間 | 現實秒數 | 佔比 |
|---|---|---|---|
| 晨間備料 | 1h | 15 秒 | 7% |
| 開門 | 1h | 15 秒 | 7% |
| 貓咪輪休 | 1h | 15 秒 | 7% |
| 午間尖峰 | 4h | 60 秒 | 29% |
| 午後大掃除 | 1h | 15 秒 | 7% |
| 悠閒午後＋VIP | 6h | **90 秒** | **43%** |

問題：
- **晨間備料只有 15 秒**，要烘焙、補糧、叫醒貓，新手幾乎做不完。建議備料階段**暫停時鐘**，玩家按「開店」才開始計時。
- **最輕鬆的時段佔最長**（90 秒），節奏會前緊後鬆。建議縮短營業到 19:00，或在 17:00–19:00 加一個「下班人潮」小高峰。
- **貓咪輪休綁死在 09:00** 不自然。建議改成貓咪體力 < 30 就自動去睡，09:00 廣播只當教學提示。
- 實作：用 `計時器` 換算時間，不要用「每幀 +0.133」累加（Scratch 掉幀時會變慢）。廣播要加防重複判斷（例如 `Last_Event_Hour`），否則條件成立的那幾幀會連續廣播。
- 廣播清單缺 **10:00 午間尖峰**、**15:00 VIP 時段**、**新一天開始** 三個事件。

## P0｜缺少的系統（無法開始調數值）

### 4. 經濟數值表
目前完全沒有數字。至少需要：
- 開局金幣、每道餐點的**基準價／食材成本／製作秒數**（建議做成 Scratch 清單 `Menu_Price`、`Menu_Cost`、`Menu_CookTime`，用 `order_dish_id` 當索引）
- 價格滑桿的**綠／黃／紅區間邊界**（例如基準價 ×1.0 / ×1.3 / ×1.6）
- 員工日薪、休息室恢復速度、家具與貓砂價格
- **二樓是否另收費？** 真實貓咪咖啡廳多半收入場費或時段費，這也是重要收入來源，目前沒提

#### 4-1. 經濟數值草案（以「正常難度第 1 天，初始現金 ¥100」為基準）

> 已與 Chuck 確認：正常難度第 1 天開局現金為 ¥100。（2026-10-18 改為 ¥500，以下試算仍是 ¥100 時的版本。）

開局 ¥100 很緊，代表第 1 天的設計重點是「先買料才能賺錢」，這很適合新手教學。以下數字是起點，供試玩後再調：

| 項目 | 售價 | 成本 | 製作時間（現實秒） | 備註 |
|---|---|---|---|---|
| 貓掌奶油餅乾（甜點） | ¥30 | ¥8 | 2 | 可晨間預製，一批 6 份 |
| 焦糖貓耳布丁（甜點） | ¥40 | ¥12 | 3 | 可晨間預製，一批 4 份 |
| 原木烤吐司（正餐） | ¥60 | ¥20 | 5 | 現做 |
| 貓臉蛋包飯（正餐） | ¥90 | ¥30 | 8 | 現做，Lv.2 解鎖 |
| 2F 吸貓入場費 | ¥50 | — | — | 每人一次，停留 30~60 遊戲分鐘 |

| 支出 | 金額 |
|---|---|
| 麵粉一袋（約 10 份甜點） | ¥40 |
| 雞蛋／肉品一份（約 5 份正餐） | ¥50 |
| 貓糧一包（3 隻貓 1 天） | ¥20 |
| 貓砂一包（2 天） | ¥15 |
| 員工日薪 | ¥80～¥120（依職位） |
| 除臭水霧機 | ¥300 |

價格滑桿區間（以售價為基準）：
- 綠色：≤ 1.0 倍，購買率 100%
- 黃色：1.0～1.4 倍，購買率 75%
- 紅色：> 1.4 倍，不點餐並扣小分

試算第 1 天：開局 ¥100，買麵粉 ¥40 和貓糧 ¥20 後剩 ¥40。來客約 12 人，平均消費（餅乾＋入場）約 ¥75，營收約 ¥900，扣掉食材成本（12 份餅乾約 ¥96）後淨賺約 ¥800。注意一袋麵粉只夠 10 份，玩家得在營業中途用剩下的 ¥40 再補一袋，這正好可以當作「喵喵速達」的教學時機。第 2 天就足以補料並存錢雇第一位員工（Lv.2 解鎖），節奏剛好。

另外建議在變數表加入 `Stock_Flour`、`Stock_Meat`、`Stock_CatFood`、`Stock_Litter`，以及結算畫面的「今日營收／成本／薪資／淨利」四行。

### 5. 勝敗與升級條件
- **階段升級條件**：要多少 Fans／評分／天數才升 Lv.2、Lv.3？莉莉安考核的通過標準是什麼？失敗會怎樣？
- **失敗條件**：金幣歸零會破產嗎？評分過低會關店嗎？還是純療癒無失敗？請明確選一種。
- **結局**：Stage 3 通關後是結束、無盡模式，還是有 Stage 4？

### 6. 顧客動線
文件沒寫一位客人完整會經過哪些點。建議寫成狀態機，例如：

```
進門 → 吧檯點餐（耐心倒數）→ 入座 → 等餐 → 用餐
     → (機率) 上 2F 吸貓 N 分鐘 → (機率) 如廁 → 吧檯結帳 → 離開
```

並寫明：
- 1F 座位數、2F 地毯可容納幾人
- 耐心歸零時在各階段的後果
- 外帶／電話預約客走哪條路線
- VIP 有什麼不同（點單、耐心、評分加權）

### 7. 庫存系統
喵喵速達可以買麵粉、肉泥、貓砂，但變數表沒有任何庫存變數，也沒寫缺料會發生什麼。需補 `Stock_Flour`、`Stock_CatFood`、`Stock_Litter` 等，以及送達時間（立即還是隔天）。

### 8. 貓咪與員工規格
- 貓咪只寫了 3 隻（橘白、賓士、長毛），是固定 3 隻還是可增加？個性差異？
- 員工好感度「與每隻店貓獨立」= 員工數 × 貓數，用二維清單存（索引 = 員工編號 × 貓數 + 貓編號）。
- 員工體力消耗速度、多低進休息室、休息多久。
- 員工有沒有能力值（速度、手藝）？喵才獵人「篩選履歷」要篩什麼？
- 上收餐人員「兼管洗手間」時，小遊戲是自動完成還是仍由玩家玩？

### 9. 手機 App 的玩法還是空的
6 個 App 只寫了功能名稱。尤其：
- **喵喵 IG**：上傳照片是怎麼操作的？拍什麼得分高？按讚怎麼換算粉絲？
- **喵信**：只是通知，還是有選項要回應？
- **即時通話**：與直接點員工下指令差別在哪？
這幾個若沒有實際玩法，建議先合併或砍掉（見 P1-5）。

## P1｜Scratch 可行性與架構

### 1. 分身上限：「4 名顧客」太保守
- Scratch 分身上限是 **300 個**，真正的瓶頸是每個分身每幀跑的腳本量與 `碰到` 判斷。
- 只開 4 名顧客，Stage 3「人潮暴增、排隊名店」做不出來。
- 建議：顧客上限依階段遞增（Lv1: 4、Lv2: 8、Lv3: 12～15），並遵守：
  - 分身移動用座標內插，不用 `碰到顏色`
  - 位置與狀態存在清單，集中由一個控制器迴圈更新
  - 頭頂氣泡、餐盤等裝飾也算分身，要一起計入預算

### 2. 尋路
Scratch 做 A* 很吃效能。建議**不做真尋路**，改用**路徑節點圖**：在清單中預先定義 10～20 個點（門口、吧檯、各座位、樓梯、洗手間、休息室、2F 各區），角色只在節點間直線移動。

### 3. 雙樓層同時模擬
`Current_Floor` 只是「玩家看哪一層」，但另一層的顧客、貓、員工必須繼續運作。
- 每個分身要有自己的 `my_floor` 私有變數
- 每幀判斷 `my_floor = Current_Floor` 才顯示，否則 `隱藏` 但邏輯照跑
- 員工跨樓層要經過樓梯節點並切換 `my_floor`

### 4. 畫面呈現：剖面 vs 切換二選一
Scratch 舞台只有 480×360。
- **上下剖面同框**：每層只剩約 160 像素高，角色會很小，但玩家能同時看到兩層，符合「跨樓層調度」主題。
- **切換視角**：畫面大、好看，但另一層出事時要靠 UI 提示（例如邊緣閃爍圖示）。
- 建議採**切換視角 + 角落小地圖／警示圖示**，並把 GDD 的地圖圖示註明為「示意圖」。

### 5. 角色清單缺項
目前缺：餐點／髒盤分身、HUD（金幣、時間、評分）、家具、顧客頭頂氣泡、樓梯、結算畫面、標題畫面、教學提示。建議列一份完整 Sprite 清單與每個角色的分身預算。

### 6. 範圍控管
以 Scratch 而言，這份企劃是大型專案（5 種員工 AI + 3 貓 + 顧客狀態機 + 6 App + 小遊戲 + 劇情）。建議分三個里程碑：

| 里程碑 | 內容 |
|---|---|
| **MVP（Stage 1）** | 單層＋二樓切換、店長單人、2 道餐點、3 隻貓、時間系統、結算畫面、存檔碼 |
| **v0.2（Stage 2）** | 價格滑桿、洗手間小遊戲、1 名員工、電話預約、手機只做 3 個 App（招募、菜單、採購） |
| **v1.0（Stage 3）** | 五職員工、IG、莉莉安考核、人潮擴充 |

## P2｜小建議

- **紅色價格區間**：客人是看到菜單才甩門，還是點了才發現？若先看到價格，建議只「不點餐並扣小分」，不要直接扣評分，否則玩家試價格會被懲罰太重。另外寫明「笑臉指標」是什麼數值。
- **3 秒擦洗小遊戲**：每天可能觸發很多次，建議第一次 3 秒、熟練度提升或員工代勞後免玩，避免重複疲勞。
- **大掃除時客人不離場**：建議寫明這段時間是否降低客流或耐心加成。
- **主角色彩**：原木色＋白＋米色很柔和，但 UI 警示（驚嘆號、怒火）需要一個對比色（例如柿橘色），文件可補一個強調色。
- **操作方式**：沒寫玩家主要靠點擊還是鍵盤移動店長；Scratch 手機版玩家沒有鍵盤，建議全點擊操作。
- **音效／BGM**：未提及，可補一節。
- **英文名**：中文「暖陽貓閣」與英文「Cat Loft Cafe」意思略不同，可考慮「Sunny Cat Loft」。
